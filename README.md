## What is this?
Boot2Flipper is an application for Flipper Zero that allows you to emulate a iPXE USB thumb drive.  

## Features
* Automatic `autoexec.ipxe` script generation
  - Configure IP address, netmask, gateway and DNS server on your Flipper Zero
  - Automatically chainload to specified URL
* UEFI and Legacy BIOS support
* Config Load/Save to/from SD card
* Support for custom iPXE EFI executable

## How does it work?
Boot2Flipper emulates a USB Mass Storage device with "virtual" FAT32 filesystem.
The Boot2Flipper application generates FAT32 File Allocation Table and `autoexec.ipxe` script and iPXE EFI Executable on the fly.  

When the file itself is requested, Boot2Flipper automatically calculates the offset from the each file's cluster number and returns the file content from the underlying flipper filesystem.  

For legacy BIOS boot, the MBR contains a small boot loader ([`tools/bios_boot/boot.S`](tools/bios_boot/boot.S)) that loads `ipxe.lkrn` and passes the generated script to it as the kernel command line, which iPXE runs on startup, and the `.B2F` writer as the initrd. Since the disk layout is generated by Boot2Flipper, the file locations are patched into the loader instead of parsing FAT.  
If you modify the loader, run `tools/bios_boot/build.sh` to regenerate `src/disk/bios_boot_image.h`.  

### Talking to the Flipper from the host (`.B2F`)
The root directory is at LBA 0x2000, and 0x2001-0x20FF is reserved for a hidden `.B2F` directory and its files, each sized to its content (other files start at 0x2100). A program on the booted machine can use them with raw sector reads and writes, without parsing FAT:

| File | LBA | Size | Content |
| --- | --- | --- | --- |
| `.B2F/info` | 0x2002 | 512 bytes | Read-only header, starts with the magic `B2F INFO` (see below) |
| `.B2F/status` | 0x2003 | 512 bytes | ASCII text shown in `status` mode, up to the first NUL (3 lines) |
| `.B2F/frame` | 0x2004 | 1024 bytes | 128x64 1-bit image shown full screen in `framebuffer` mode. Rows of 16 bytes, least significant bit is the leftmost pixel (XBM), 1 is black |
| `.B2F/mode` | 0x2006 | 512 bytes | What the Flipper shows, an ASCII word: `status` (default, also for unknown words), `framebuffer` or `prompt` (asks `.B2F/prompt/`, the Flipper writes `status` back once answered) |
| `.B2F/prompt/type` | 0x2011 | 512 bytes | `choice` (a list, the default), `confirm` (two buttons) or `text` |
| `.B2F/prompt/question` | 0x2012 | 512 bytes | The question. Lists and keyboards show its first line |
| `.B2F/prompt/options` | 0x2013 | 1024 bytes | One per line. Confirm: the positive (OK key) then the negative (Back key) button, Yes/No if none, only OK if one. Text: the default. A choice without options is a Yes/No confirm |
| `.B2F/prompt/kbdtype` | 0x2015 | 512 bytes | Keyboard for `text`: `text` (default), `ip` or `number` |
| `.B2F/prompt/answer` | 0x2016 | 512 bytes | Read-only. `pending\n` while asking, then `ok\n<value>\n` (the option or text) or `cancel\n` (Back on the Flipper, except on a confirm with a Back button) |

The LBAs are the same for every boot method. To find the disk (or the area, if the layout ever changes), look for the magic in `info`. Its layout, little-endian:

| Offset | Size | Content |
| --- | --- | --- |
| 0 | 8 | `B2F INFO` |
| 8 | 2 | Version (1) |
| 10 | 2 | Entry count |
| 16 | 32 each | Entry: name (16, NUL padded), LBA (4), size in bytes (4), flags (4, bit 0 = writable), reserved (4) |

Write the frame's 2 sectors in one command, so it isn't shown half updated. The writers are in `.B2F/bin` from 0x2020, the sectors before it are kept for more files.  
To ask the user without the writers: write the prompt files, write `prompt` to the mode, then read the answer sector until it is not `pending` (raw reads, so no cache gets in the way).  
Other writes don't change the disk: the free space is marked as bad clusters, so operating systems see a full disk and can't add files, and writes outside `.B2F` are dropped.

#### From iPXE
The generated script sets `${b2f}` to a writer on the disk (`.B2F/bin/b2f.efi` on UEFI, `.B2F/bin/b2f.pxe` on BIOS), so a chainloaded script can use:

```
imgexec ${b2f} status Downloading kernel...\nPlease wait
imgexec ${b2f} frame logo.bin
imgexec ${b2f} mode framebuffer
imgexec ${b2f} clear
```

To ask the Flipper's user, fill in the prompt and run `prompt`, which waits for the answer and fails if the user pressed Back. `${${b2f_answer}}` is the answer (the generated script points `${b2f_answer}` at where the writer left it):

```
imgexec ${b2f} question Which OS?
imgexec ${b2f} options Ubuntu|Debian|Windows
imgexec ${b2f} prompt choice && set os ${${b2f_answer}} || goto cancelled

imgexec ${b2f} question Server IP
imgexec ${b2f} options 192.168.0.10
imgexec ${b2f} kbdtype ip
imgexec ${b2f} prompt text && set server ${${b2f_answer}} || goto cancelled

imgexec ${b2f} question Reinstall the OS?\nAll data will be erased.
imgexec ${b2f} options Erase|Keep
imgexec ${b2f} prompt confirm && set choice ${${b2f_answer}} || goto cancelled
```

`\n` starts a new line. `clear` empties the status and frame and goes back to `status` mode. For `frame`, UEFI reads an image fetched with `imgfetch http://server/logo.bin logo.bin`, BIOS opens the given URI (e.g. `http://server/logo.bin`).
This needs the `-legacy` iPXE builds: the current `ipxe.efi` and `ipxe.lkrn` take over the USB controller, so the Flipper's disk is gone once iPXE runs (booting still works, the writer then fails with an error).
The writers are built with `tools/b2f_efi/build.sh` and `tools/b2f_pxe/build.sh`.

## Usage
### How to setup iPXE files?
1. Install Boot2Flipper on your Flipper Zero
2. Open `Boot2Flipper` application on your Flipper Zero
3. Open `qFlipper` or other file transfer application (e.g. [`f0-mtp`](https://github.com/Alex4386/f0-mtp))
4. Head to `SD Card` -> `apps_data` -> `boot2flipper`
5. Create `ipxe` directory
6. Download [`ipxe.efi`](https://boot.ipxe.org/x86_64-efi/ipxe.efi) and [`ipxe.lkrn`](https://boot.ipxe.org/ipxe.lkrn) from [boot.ipxe.org](https://boot.ipxe.org) and put them into `ipxe` directory.
   To show status on the Flipper from iPXE (see [`.B2F`](#talking-to-the-flipper-from-the-host-b2f)), use [`ipxe-legacy.efi`](https://boot.ipxe.org/x86_64-efi/ipxe-legacy.efi) and [`ipxe-legacy.lkrn`](https://boot.ipxe.org/ipxe-legacy.lkrn) instead, renamed to `ipxe.efi` and `ipxe.lkrn`.

### How to use Boot2Flipper?
1. Open `Boot2Flipper` application on your Flipper Zero
2. (Optional) Load configuration from SD card
3. Configure Network (DHCP or Static IP)
4. (Static IP only) 
   1. configure IP address, netmask, gateway and DNS server at `NetworkSettings` menu.
      All four octets are edited on one screen: type the digits and it moves to the next octet once no more digits fit (e.g. after `192` or `0`), or use the `◀`/`▶` buttons to move between octets. Typing replaces a newly focused octet, the backspace key deletes into the previous octet, and long press OK on it clears all.
   2. (Static IP Only) Configure Network Interface other than `auto` (If it is left to `auto`, it will automatically use `net0` interface)
5. Select `Boot Method`. `Hybrid` (default) boots on both legacy BIOS and UEFI.
   `UEFI` is a spec-compliant GPT disk with a protective MBR, `MBR` is an MBR-only disk.
   If your UEFI firmware doesn't detect the disk in `Hybrid`, switch to `UEFI`.
6. If you want to drop to iPXE shell, Set Chainload to `Disabled`.
   1. Else, Set the ChainloadURL to your desired URL.
      The URL keyboard has `.`, `/`, `:`, `-` on the letter layers; the `ABC`/`123`/`abc` key switches to uppercase and digits/symbols. Long press OK types the other case, long press the backspace key clears the text. Press `save` when done.
7. (Optional) Save configuration to SD card
8. Press `Start` button to start emulating USB Mass Storage device
9. On your PC, Select Boot Device labelled as `FLIPPER Boot2Flipper 1.0` or similar.
10. Your Flipper Zero will report as it is reading `ipxe.lkrn` or `bootx64.efi` file., due to flipper zero's limitation, it will take some time to read and send the file to PC.
11. Congratulations, You'll see iPXE booting up on your PC!

## FAQ
1. **Why didn't you use other sizes less than `128MB`?**  
   This is due to some BIOSes not respecting `ESP` partition sizes that are less than `100MB`.
   This is a known issue with some UEFI implementations. Due to this, if you have Debug logging enabled in Flipper Zero, initial FAT32 FAT scan may take a while. So either disable Debug logging or wait.
